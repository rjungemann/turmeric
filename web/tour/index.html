01 — Algebraic Effects

Side effects,
tamed.

Declare what your functions can do, not how they do it. Effects are first-class operations that any caller can intercept and handle, without touching your core logic.

Swap between production, test, and mock handlers at the call site. The type system ensures you never forget to handle an effect.

defeffect · perform · handle · resume
effects.tur
;; Declare effects as first-class operations (defeffect Ask [] :int) (defeffect Log [msg :str] :void) (defn compute [] :int (perform (Log "computing...")) (* (perform (Ask)) 2)) ;; Production: logs to stdout, asks for real value (handle (compute) (Ask [] k) (resume k 21) (Log [msg] k) (do (println msg) (resume k))) ;; prints: computing... returns: 42 ;; Test: suppress logs, supply fixed value (handle (compute) (Ask [] k) (resume k 0) (Log [_] k) (resume k)) ;; (silent) returns: 0

02 — Typeclasses

Polymorphism
that scales.

Define a typeclass once, implement it for any type, and let the compiler verify that every call site has a valid instance. Zero virtual tables, zero runtime cost.

Typeclass constraints keep your functions general without sacrificing precision. The ^Show syntax reads "must implement Show."

defclass · definstance · ^Constraint
typeclasses.tur
(defclass Show [a] (show [x] :str)) (defdata Color (Red) (Green) (Blue)) (definstance Show [Color] (show [c] (match c (Red) "red" (Green) "green" (Blue) "blue"))) ;; ^Show means: x must have a Show instance (defn display [^Show a x] :void (println (show x))) (display (Red)) ;; => "red" (display (Blue)) ;; => "blue"

03 — ADTs & Pattern Matching

Data that
speaks.

Algebraic data types let you model your domain precisely. defdata defines a sum type; match deconstructs it, exhaustively, with compiler-checked completeness.

No null pointers, no missing branches. Every case is forced to the surface where you can handle it.

defdata · defgadt · match
expr.tur
;; A small expression language (defdata Expr (Lit :int) (Add Expr Expr) (Mul Expr Expr) (Neg Expr)) (defn eval [e] :int (match e (Lit n) n (Add l r) (+ (eval l) (eval r)) (Mul l r) (* (eval l) (eval r)) (Neg x) (- 0 (eval x)))) ;; (2 + 3) * -4 => -20 (println (eval (Mul (Add (Lit 2) (Lit 3)) (Neg (Lit 4))))) ;; => -20

04 — Delimited Continuations

Control that
bends.

Delimited continuations let you capture, store, and resume a slice of the call stack as an ordinary value. Coroutines, generators, and backtracking are just library code.

reset delimits a region; shift captures the continuation up to that boundary and lets you reify it as a function you call at will.

reset · shift · delimited
gen.tur
;; Build a list lazily with shift/reset (defn yield [v] :any (shift k (cons v (k)))) (defn collect [thunk] :list (reset (do (thunk) nil))) ;; Generator that yields three values (println (collect (fn [] (yield 10) (yield 20) (yield 30)))) ;; => (10 20 30) ;; Same primitives power backtracking, ;; async/await, and cooperative scheduling.

05 — Macro System

Syntax that
grows.

Turmeric's macro system runs at compile time and operates directly on the syntax tree. Define new control flow, DSLs, or syntactic sugar without any runtime overhead.

Quasiquote (`) and unquote (~) make template-style code construction natural and readable. The result is indistinguishable from hand-written code.

defmacro · quasiquote · unquote · splice
macros.tur
;; `unless` -- inverse of when (defmacro unless [test & body] `(when (not ~test) ~@body)) ;; multi-branch conditional -- `cond` (defmacro cond [& clauses] (if (nil? clauses) nil `(if ~(first clauses) ~(second clauses) (cond ~@(rest (rest clauses))))) ;; Usage: clean multi-branch dispatch (defn sign [n :int] :str (cond (< n 0) "negative" (= n 0) "zero" (> n 0) "positive"))

06 — Reference Counting

Memory without
compromise.

Turmeric manages heap values through explicit reference counting with compiler-assisted elision. You get deterministic cleanup -- no GC pauses, no dangling pointers, no runtime surprises.

rc/clone increments the count; rc/drop decrements it. When the count hits zero, the value is freed immediately -- right there, at that line.

rc/of · rc/clone · rc/drop · rc/strong-count
memory.tur
;; Heap-allocate a value with rc/of (let [data (rc/of 42)] (println (rc/strong-count data)) ;; => 1 ;; Clone increments the reference count (let [alias (rc/clone data)] (println (rc/strong-count data)) ;; => 2 (println (= @data @alias)) ;; => true (rc/drop alias)) ;; count -> 1 (println (rc/strong-count data)) ;; => 1 (rc/drop data)) ;; freed here, no GC

07 — Higher-Order Functions

Functions as
values.

Functions are first-class in Turmeric -- pass them, return them, store them, compose them. Closures capture their environment lexically, with full type inference.

The standard library's map, filter, and reduce work uniformly over any foldable structure -- not just lists.

fn · closure · map · filter · reduce
closures.tur
;; Closures capture their lexical environment (defn make-adder [n :int] :(fn [:int] :int) (fn [x :int] (+ n x))) (let [add5 (make-adder 5) add10 (make-adder 10)] (println (add5 3)) ;; => 8 (println (add10 7))) ;; => 17 ;; Pipeline transformations with map + filter (let [nums [1 2 3 4 5]] (println (map (fn [x] (* x x)) (filter (fn [x] (= (% x 2) 0)) nums)))) ;; => (4 16)

08 — Neoteric Syntax

Two syntaxes,
one language.

Not a fan of nested parentheses? Switch to Neoteric mode with a single #lang declaration. Function calls use f(args) notation while keeping all of Turmeric's semantics intact.

Both syntaxes compile to the same AST. Mix and match across files in the same project -- or share libraries between Turmeric and Neoteric code freely.

#lang turmeric/neoteric · f(args)
classic.tur
;; Standard Lisp-style syntax (defn factorial [n :int] :int (if (<= n 1) 1 (* n (factorial (- n 1))))) (println (factorial 10)) ;; => 3628800 (let [xs [1 2 3 4 5]] (println (filter (fn [x] (> x 2)) xs))) ;; => (3 4 5)
#lang turmeric/neoteric (defn factorial [n :int] :int (if <=(n 1) 1 *(n factorial(-(n 1))))) println(factorial(10)) ;; => 3628800 (let [xs [1 2 3 4 5]] println(filter((fn [x] >(x 2)) xs))) ;; => (3 4 5)

09 — Runtime Contracts

Correctness
by contract.

When the type system can't catch every invariant, contracts step in. require! asserts preconditions at the call site; ensure! checks postconditions on return. Both produce clear, structured errors in development and can be stripped in release builds.

Contracts are opt-in and composable -- layer them wherever correctness matters most without changing function signatures.

require! · ensure! · assert!
contracts.tur
;; require! asserts preconditions (defn safe-sqrt [x :float] :float (require! (>= x 0.0) "safe-sqrt: x must be non-negative") (sqrt x)) ;; ensure! checks postconditions on return (defn sorted-insert [vec v] :vec (require! (sorted? vec) "vec must be sorted before insert") (let [result (insert-sorted vec v)] (ensure! (sorted? result) "postcondition: result must be sorted") result)) ;; assert! for general invariant checks (assert! (= (safe-sqrt 4.0) 2.0) "sqrt(4) should be 2")

10 — Spice Package Manager

Dependencies,
simplified.

One build.tur file describes your package and every dependency -- called spices. Git URLs and version refs are all you need. No separate binary, no lock file ceremony.

Need a C library? Add it under :cmake-deps. Turmeric fetches, builds, and links it automatically via CPM -- no manual CMake required.

defpackage · :spices · :cmake-deps
build.tur
(defpackage my-app :name "my-app" :version "0.1.0" :entry "src/main.tur" ;; Turmeric dependencies -- called spices :spices { "json" {:url "https://github.com/alice/tur-json" :ref "v1.2.0"} "http" {:url "https://github.com/bob/tur-http" :ref "v3.0.0"} } ;; C/CMake dependencies (CPM-compatible) :cmake-deps { "sqlite3" {:url "https://github.com/sqlite/sqlite" :ref "version-3.45.0"} "raylib" {:url "https://github.com/raysan5/raylib" :ref "5.0"} })
