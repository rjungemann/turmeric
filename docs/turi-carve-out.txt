# turi carve-out list -- EX_* expression kinds the tree-walking interpreter
# (src/turi/eval.c) intentionally does NOT implement.
#
# Format: one `EX_NAME -- one-line rationale` per line.  Blank lines and lines
# beginning with `#` are ignored.  tools/check_turi_parity.py reads this file:
# any EX_* kind that has no `case` arm in eval.c MUST appear here, and any entry
# here that is actually handled (or names a nonexistent kind) is flagged as
# stale.  Keep the rationale short and point at the tracking doc/report.
#
# See docs/upcoming/v1/turi-parity-post-v1-plan.md (Phases TI3.2, TI7) and
# docs/guides/turi-parity-guide.md for the full discussion.

# --- CPS transform (Risks #5 / Sequencing) -------------------------------
# (call/cc f) / (escape f) (EX_CALLCC) are now implemented in the interpreter
# (eval_callcc_escape in eval.c): an undelimited one-shot upward escape modeled
# with a setjmp/longjmp landing pad, with the (k v) sugar lowered (in elab) to
# tur_escape_resume.  EX_CPS_CONT_APP is a CPS-pipeline node the elaborator
# never emits (the interpreter stops at elaboration), so it stays carved.
EX_CPS_CONT_APP -- CPS continuation application; never produced by the elaborator (CPS-pipeline only)

# --- Context-capturing delimited control (TI3.2) -------------------------
# Abortive shift/reset/shift0 (TI3.1) and the context-CAPTURING serial-shift /
# cloneable-shift (TI3.2) are now implemented in the interpreter: EX_SERIAL_RESET
# / EX_CLONEABLE_RESET reify the delimited context at runtime (ts_capture_and_run
# in eval.c) and hand the receiver a resumable continuation.  EX_SERIAL_SHIFT /
# EX_CLONEABLE_SHIFT therefore no longer need a carve-out -- they are reached only
# through their enclosing reset, never evaluated standalone.  See
# docs/archive/turi-capturing-shift-unimplemented.md.

# --- Inline-C-bound literal sugar (TI1 / TI7) ----------------------------
# The sym/cons-list literals only appear paired with user inline-C in the
# existing fixtures (__tur_sym field reads, __tur_cons_cell walks), which is a
# permanent interpreter carve-out (TI7).  Landing them usefully requires native
# sym=?/sym->str and cons-head/cons-tail overrides, not just the literal case
# arm; deferred until those natives exist.
EX_SYM_LIT -- interned symbol literal; inline-C-bound, needs native sym ops (TI1/TI7)
EX_CONS_LIST -- cons-list literal; inline-C-bound, needs native cons ops (TI1/TI7)
