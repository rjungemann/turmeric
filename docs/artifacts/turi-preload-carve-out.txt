# turi interpreter preload carve-outs
#
# Modules the COMPILED path auto-loads (stdlib_files[], src/main.c) but the
# --interpret/tur eval STATIC prelude (prelude[] in cmd_eval_h, src/main.c) does
# NOT list.  check_turi_native_parity.py computes the gap set as
# compiled-auto-load minus that prelude[] array; every gap module must carry a
# one-line rationale here (an undocumented gap fails the build; a stale entry --
# one now in prelude[] or no longer auto-loaded -- also fails).
#
# NOTE: "gap relative to prelude[]" is not the same as "unavailable at runtime".
# json.tur and schema.tur are preloaded unconditionally by the JR0/RD
# reader-macro auto-load blocks that run right after prelude[] (so #json(...) and
# #json-str<T>(...) lowerings resolve), so their public names DO resolve under
# --interpret; they are simply loaded outside the prelude[] array the parity
# ratchet tracks.  (The retired TUR_TURI_FULL_PRELUDE=1 opt-in used to load them
# a second way -- JR0/RD already covers it unconditionally, so the flag and its
# gate test were removed.)
#
# Format:  <module>.tur -- <one-line rationale>
# See docs/archive/history/turi-harness-flip-reconciliation.md and
#     docs/archive/history/turi-open-reports-prereqs.md (prereqs 2c, 3a, 3b).

json.tur    -- reader-backed (#json / -Xjson); not in the static prelude[], but unconditionally preloaded by the JR0 reader-macro auto-load block after prelude[].
schema.tur  -- reader-backed (#json-str<T>) and depends on json.tur; not in prelude[], unconditionally preloaded by the RD block right after json.tur.
