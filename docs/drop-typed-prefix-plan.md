# Plan: Drop the `t-` prefix from typed collection types

> **Status:** Approved -- Option A locked in; ready to start Phase 1
> **Tracked across repos:** `turmeric` (stdlib + compiler), `turmeric-spices` (companion PR)
> **Last Updated:** 2026-05-25
> **Type:** Stdlib API rename / breaking change

---

## Motivation

The typed parameterized collections (`tmap`, `tvec`, `tlist`, `toption`,
`tresult`, `tset`, `tpair`, `tslice`, `tgrid`, `tzipper`, `tmutmap`) carry a
`t-` prefix that exists for one reason only: to disambiguate them from the
older untyped modules of the same shape (`map`, `vec`, `list`, ...). Those
untyped modules are now explicitly marked **Deprecated -- superseded by
tur/t\<X\>** in their own docstrings (see `stdlib/vec.tur:6`,
`stdlib/map.tur:7`, etc.).

The prefix has outlived its purpose:

- New code should be written against the typed versions, but the `t-`
  prefix reads like Hungarian notation in a language that otherwise has
  none.
- The collision only exists because the legacy modules still ship. Once
  they are removed, `Map`, `Vec`, `List`, etc. are the obvious names.
- Module identifiers (`tur/tmap`) and function identifiers (`tmap-new`,
  `tvec-push!`) both inherit the wart, so it shows up in every call site.

**Goal:** rename every t-prefixed module, file, and function to its
un-prefixed name. After the rename, `(import map)` is the typed Map[K V]
API and there is no deprecated parallel.

## Scope inventory

### t-prefixed stdlib modules (11)

| Module       | File                  | Type defined | Function prefix |
|--------------|-----------------------|--------------|-----------------|
| `tur/tmap`   | `stdlib/tmap.tur`     | `Map[K V]`   | `tmap-*`        |
| `tur/tvec`   | `stdlib/tvec.tur`     | `Vec[A]`     | `tvec-*`        |
| `tur/tlist`  | `stdlib/tlist.tur`    | `List[A]`    | `tlist-*`       |
| `tur/toption`| `stdlib/toption.tur`  | `Option[A]`  | `toption-*`     |
| `tur/tresult`| `stdlib/tresult.tur`  | `Result[A B]`| `tresult-*`     |
| `tur/tset`   | `stdlib/tset.tur`     | `Set[A]`     | `tset-*`        |
| `tur/tpair`  | `stdlib/tpair.tur`    | `Pair[A B]`  | `tpair-*`       |
| `tur/tslice` | `stdlib/tslice.tur`   | `Slice[A]`   | `tslice-*`      |
| `tur/tgrid`  | `stdlib/tgrid.tur`    | `Grid[A]`    | `tgrid-*`       |
| `tur/tzipper`| `stdlib/tzipper.tur`  | `Zipper[A]`  | `tzipper-*`     |
| `tur/tmutmap`| `stdlib/tmutmap.tur`  | `MutableMap[K V]` | `tmutmap-*`|

Type names (`Map`, `Vec`, `List`, ...) are already prefix-free -- only
file names, module paths, and function symbols need rewriting.

### Legacy un-prefixed modules (10)

These currently *own* the unprefixed names and must move out of the way:

`stdlib/list.tur`, `stdlib/map.tur`, `stdlib/option.tur`,
`stdlib/pair.tur`, `stdlib/result.tur`, `stdlib/set.tur` (if present),
`stdlib/slice.tur`, `stdlib/vec.tur`, `stdlib/grid.tur`,
`stdlib/zipper.tur`.

Each is marked deprecated in its own docstring. We need a disposition
decision (see "Open question" below).

### Call sites

- **58** test fixtures under `tests/fixtures/**/input.tur` reference
  `tmap-*` / `tvec-*` / etc. (10 of them also live under
  `tests/fixtures/typed/`).
- **`stdlib/docstrings.tur`** -- auto-generated lookup table; regenerated
  by `tools/gendocs.py --emit-tur`. No manual edits.
- **`stdlib/sized-bits.tur` (41 hits)** is the largest non-test caller in
  stdlib; cross-stdlib uses of typed collections also appear in
  `tmutmap.tur`, `tset.tur`, `tmap.tur`, `tvec.tur`, `tgrid.tur`,
  `tslice.tur`, `tzipper.tur`, `tlist.tur`, `tpair.tur`, `tresult.tur`,
  `toption.tur` (self/cross references).
- **`src/main.c:626-638`** -- the auto-load list hardcodes the eleven
  filenames (`"tmap.tur"`, `"tvec.tur"`, ...). Must be updated in lockstep
  with the file renames.
- **`tests/doctest-generated/`** -- generated per-module test files
  (`tmap.tur`, `tvec.tur`, `tlist.tur`, `tmutmap.tur`, ...). Regenerated
  by the doctest harness; no manual edits.
- **Docs** -- API HTML under `docs/api/` is regenerated by `just docs`;
  hand-written guides under `docs/guides/` need a sweep.
- **External**: `../turmeric-spices/` may import t-modules. Out of scope
  for the initial PR but listed in the rollout section.

## Disposition of the deprecated untyped modules: Option A (decided)

The legacy un-prefixed modules (`stdlib/map.tur`, `stdlib/vec.tur`, ...)
are deleted outright. Each has been marked **Deprecated -- superseded
by tur/t\<X\>** in its own docstring since Phase TM0 / TC1-A; the typed
versions cover every use case.

A spot-check of `../turmeric-spices/` confirms zero imports of the
typed module paths (`tur/tmap`, `tur/tvec`, ...) and zero callers of
their function prefixes (`tmap-*`, `tvec-*`, ...). The earlier
appearance of `bitmap-*` matches in `frame/buffer.tur` is unrelated --
those are the frame spice's own bitmap helpers, not stdlib `tmap-*`.
So the spices repo will only need to absorb the rename, not migrate
away from a deprecated API first.

Two alternatives were considered and rejected:

- *Rename legacy modules under `stdlib/legacy/`* -- doubles the
  stdlib file count to preserve code we have already labelled
  deprecated.
- *Rename functions only, keep module file names* -- leaves the
  inconsistency `tur/tmap` (module) vs `map-*` (functions), which is
  worse than today.

## Phased rollout

### Phase 1 -- Disposition of legacy modules (Option A)

1. Audit every reference to a legacy untyped module across the monorepo
   and `../turmeric-spices/` (if checked out):
   - `grep -rn "import \(list\|map\|option\|pair\|result\|set\|slice\|vec\|grid\|zipper\)\b"`
   - `grep -rn "tur/\(list\|map\|...\)\b"`
2. Migrate any surviving caller to the typed equivalent.
3. Delete `stdlib/list.tur`, `stdlib/map.tur`, `stdlib/option.tur`,
   `stdlib/pair.tur`, `stdlib/result.tur`, `stdlib/slice.tur`,
   `stdlib/vec.tur`, `stdlib/grid.tur`, `stdlib/zipper.tur`.
4. Remove the legacy entries from the autoload list in `src/main.c`
   (currently `"result.tur"` and any other unprefixed entries -- the
   typed `tresult.tur` is what stays).
5. Re-run `just test`. Land as a stand-alone commit so the rename diff
   stays readable.

### Phase 2 -- Mechanical rename in stdlib

For each pair (`tmap` -> `map`, `tvec` -> `vec`, ...):

1. `git mv stdlib/tmap.tur stdlib/map.tur`
2. In the renamed file:
   - Update the module docstring header (`;;; tur/tmap` -> `;;; tur/map`)
   - Rename every `tmap-*` symbol to `map-*` (defn, defmacro, exports,
     intra-file callers). Use a single `sed -i 's/\btmap-/map-/g'`
     followed by a manual diff review.
3. Repeat for the other 10 modules.
4. Update `stdlib/sized-bits.tur` and any other stdlib caller in one
   sweep (`sed`-based, list of prefixes piped in).
5. Update `src/main.c:626-638` auto-load filenames.
6. Run `just docs --emit-tur stdlib/docstrings.tur` to regenerate the
   lookup table.

### Phase 3 -- Test-fixture rename

1. Rename fixture directories where the name encodes the module
   (`tests/fixtures/tmap-basic` -> `tests/fixtures/map-basic`, etc.)
   and update any `tests/fixtures/typed/<name>` similarly. Inside each
   `input.tur` rewrite the function-call prefixes.
2. Rerun the doctest harness so
   `tests/doctest-generated/{tmap,tvec,tlist,tmutmap}.tur` regenerate
   under the new names.
3. `just test` from a clean checkout to confirm CTest discovers all
   renamed fixtures.

### Phase 4 -- Docs sweep

1. `grep -rn "tmap\|tvec\|tlist\|toption\|tresult\|tset\|tpair\|tslice\|tgrid\|tzipper\|tmutmap" docs/` -- update every mention in hand-written guides under `docs/guides/`. Archive plans (`docs/archive/`) are historical -- leave them as-is so the phase tags they reference remain meaningful.
2. `just docs` to regenerate `docs/api/`.
3. Update `CLAUDE.md` if any examples show t-prefixed calls (none today, but verify after the rename).

### Phase 5 -- Downstream / spices rollout

After the turmeric PR lands, do the same rename pass over the sibling
`../turmeric-spices/` checkout. As of 2026-05-25 the spices repo has
zero direct callers of `tmap-*` / `tvec-*` / etc. and zero imports of
`tur/tmap` / `tur/tvec` / etc., so this phase is primarily *defensive
verification* -- but it must still run in lockstep so the SC8 per-spice
typecheck matrix stays green.

1. **Pin the consuming turmeric commit.** Build `tur` from the
   post-rename commit and point `../turmeric-spices/` at it (whatever
   pinning mechanism the spices CI uses -- submodule, version file, or
   local checkout). Without this step a CI run will use an old `tur`
   that still expects `tmap.tur` in the autoload list.
2. **Re-run the scans against `../turmeric-spices/`.** Use the same
   greps as Phase 1 step 1, plus the type-ascription form:
   ```
   grep -rEn "\b(tmap|tvec|tlist|toption|tresult|tset|tpair|tslice|tgrid|tzipper|tmutmap)\b" ../turmeric-spices/
   grep -rEn "tur/(tmap|tvec|tlist|toption|tresult|tset|tpair|tslice|tgrid|tzipper|tmutmap)\b" ../turmeric-spices/
   grep -rEn "\b(tmap|tvec|tlist|toption|tresult|tset|tpair|tslice|tgrid|tzipper|tmutmap)-" ../turmeric-spices/
   ```
   Inspect every hit; rule out false positives (e.g. `bitmap-*` in
   `frame/buffer.tur`); rewrite real call sites with the same
   mechanical `sed` recipe used in Phase 2.
3. **Sweep spice docstrings and READMEs.** Spice-level docs may
   mention the typed APIs in `Example:` blocks or prose. Same `grep`,
   plain prose this time.
4. **Run the SC8 matrix locally.** From `../turmeric-spices/`:
   ```
   for f in $(find spices -name '*.tur'); do tur check "$f" || echo "FAIL $f"; done
   ```
   Every file must pass under the renamed stdlib. Any spice that
   previously carried a `requires.typecheck-skip` marker tied to a
   typed-collection failure should now be reconsidered for unskipping
   (cross-reference `docs/skipped-spices-cleanup-plan.md`).
5. **Open the companion PR.** Title it to make the dependency explicit
   (e.g. "Rename t-prefixed stdlib APIs -- spices companion"). Include
   the turmeric PR / commit hash in the body so reviewers can build
   the right `tur` to test against.
6. **Land both together.** Merge order: turmeric PR first, then the
   spices PR within a short window. While the spices PR is unmerged,
   anyone running `tur check` from a freshly-built turmeric against
   `main` of spices will see breakage; keep the gap minimal.
7. **Post-merge cleanup.** Drop any `requires.spices` skip markers in
   the turmeric repo that were tied to the rename, and update the
   companion-to / cross-repo notes in
   `docs/skipped-spices-cleanup-plan.md` if relevant.
8. **Changelog.** Announce the breaking change (top of `CLAUDE.md` for
   one phase, then removed; mention the rename in any spice-level
   `CHANGELOG.md` that exists).

## Risk and mitigations

- **Silent collisions with shadowed symbols.** A bare `sed s/tmap-/map-/`
  could hit a comment or string that happens to share the prefix. Run
  the sed, then `git diff --stat` and spot-check a few files; the rename
  is mechanical enough that a code review of the full diff is feasible.
- **Doctest drift.** `tests/doctest-generated/` is rebuilt from
  docstrings; if Phase 2 misses a function reference in an `Example:`
  block, the regenerated test will fail with a stale name. The regen +
  `just test` in Phase 2 step 6 catches this.
- **External consumers.** Covered by the Option A discussion above; if
  the audit in Phase 1 step 1 finds surviving in-tree callers we did not
  expect, revisit the disposition decision before continuing.
- **Auto-load ordering.** The list in `src/main.c` currently places
  `result.tur` *before* the typed block (line 625), because the
  un-prefixed `ok`/`err`/`ok?` helpers are globally available. With
  Option A, those helpers come from the renamed `result.tur` (formerly
  `tresult.tur`), so the comment at `src/main.c:621-624` needs a refresh.

---

## Acceptance criteria

1. No file under `stdlib/` starts with `t` followed by a previously-typed
   collection name; no defn / defmacro symbol begins with `tmap-`,
   `tvec-`, etc.
2. `just test` is green from a clean checkout.
3. `just docs` produces `docs/api/` with `map.html`, `vec.html`, ...
   (no `tmap.html`).
4. `(import map)` resolves to the typed `Map[K V]` API; the old untyped
   module is gone (Option A) or moved (Option B).
5. The `src/main.c` autoload list references the new filenames and the
   comment around `result.tur` reflects the new layout.
