# CMake / CPM Integration Plan for Turmeric Spice

> **Status:** Speculative -- v2.x target (after core Spice ships)
> **Depends on:** [package-management-plan.md](package-management-plan.md)
> **Scope:** Two directions of integration
>   1. Turmeric projects consuming C/CMake packages (`:cmake-deps`)
>   2. CMake projects consuming Turmeric packages (CMake plugin, stretch goal)

---

## Overview

Turmeric's primary package system (Spice) handles Turmeric-to-Turmeric
dependencies. This document specifies how Turmeric interoperates with the CMake
ecosystem in two directions:

- **Inbound**: A `build.tur` can pull in C/C++ libraries published as CMake /
  CPM packages via the `:cmake-deps` block.
- **Outbound** (stretch goal): A Turmeric package can be imported by a CMake
  project via a generated `TurmericConfig.cmake` and a `FindTurmeric.cmake`
  helper.

In both cases the user writes only Turmeric (in `build.tur`). CMake is an
implementation detail, not a user-facing tool.

---

## Part 1: Inbound -- Turmeric Consuming CMake Packages

### How it works end-to-end

1. The user adds a C library to their `build.tur` `:cmake-deps` block.
2. `tur fetch` reads `:cmake-deps`, generates `cmake/SpiceDeps.cmake`, and
   invokes `cmake --build cmake/` to fetch and build the C libraries.
3. `tur build` reads the build artifacts produced by CMake and passes the
   necessary `-I` (include), `-L` (library path), and `-l` (link flags) to the
   Turmeric compiler and the final C compilation step.

Users never run `cmake` manually.

### The `:cmake-deps` block

```scheme
:cmake-deps {
  ;; Minimal: URL + ref
  "raylib" {:url "https://github.com/raysan5/raylib" :ref "5.0"}

  ;; With CMake cache options
  "cjson"  {:url     "https://github.com/DaveGamble/cJSON"
            :ref     "v1.7.16"
            :options {:CJSON_BUILD_SHARED_LIBS "OFF"
                      :CJSON_OVERRIDE_BUILD_SHARED_LIBS "ON"}}

  ;; Name on disk can differ from CMake target name
  "sqlite" {:url        "https://github.com/sqlite/sqlite"
            :ref        "version-3.45.0"
            :cmake-name "SQLite3"          ; maps to find_package(SQLite3)
            :targets    ["SQLite::SQLite3"]}

  ;; Local CMake package (for development)
  "mylib"  {:path      "../my-c-lib"
            :cmake-name "MyLib"
            :targets    ["MyLib::mylib"]}
}
```

Key fields:

| Field | Required | Description |
|---|---|---|
| `:url` | Yes (or `:path`) | Git URL to the CMake project |
| `:ref` | Yes (with `:url`) | Git tag, branch, or commit SHA |
| `:path` | Alt to `:url` | Local directory for development |
| `:options` | No | CMake cache variables to set (`-DKEY=VALUE`) |
| `:cmake-name` | No | `find_package` name if different from the key |
| `:targets` | No | CMake targets to link against (defaults to `<name>::<name>`) |

### Generated `cmake/SpiceDeps.cmake`

`tur fetch` produces this file automatically. Do not edit it by hand.

```cmake
# cmake/SpiceDeps.cmake -- AUTO-GENERATED by `tur fetch`. Do not edit.
cmake_minimum_required(VERSION 3.20)
project(SpiceDeps)

include(FetchContent)

# raylib
FetchContent_Declare(raylib
  GIT_REPOSITORY https://github.com/raysan5/raylib
  GIT_TAG        5.0
)
set(BUILD_SHARED_LIBS OFF CACHE BOOL "" FORCE)
set(BUILD_EXAMPLES    OFF CACHE BOOL "" FORCE)
FetchContent_MakeAvailable(raylib)

# cjson
FetchContent_Declare(cjson
  GIT_REPOSITORY https://github.com/DaveGamble/cJSON
  GIT_TAG        v1.7.16
)
set(CJSON_BUILD_SHARED_LIBS          OFF CACHE BOOL "" FORCE)
set(CJSON_OVERRIDE_BUILD_SHARED_LIBS ON  CACHE BOOL "" FORCE)
FetchContent_MakeAvailable(cjson)
```

### Compiler integration

After CMake builds the C deps, `tur build` reads a generated
`cmake/spice-deps-manifest.json`:

```json
{
  "raylib": {
    "include_dirs": ["/path/to/build/cmake/_deps/raylib-src/include"],
    "link_dirs":    ["/path/to/build/cmake/_deps/raylib-build/lib"],
    "link_libs":    ["raylib"]
  },
  "cjson": {
    "include_dirs": ["/path/to/build/cmake/_deps/cjson-src"],
    "link_dirs":    ["/path/to/build/cmake/_deps/cjson-build"],
    "link_libs":    ["cjson"]
  }
}
```

These flags are forwarded to `cc` when compiling the generated `.c` output.

### Using C libraries from Turmeric code

C headers are imported with `extern-c` and `include-c`:

```scheme
;; src/window.tur
(include-c "raylib.h")

(extern-c InitWindow   [width :int height :int title :cstr] :void)
(extern-c BeginDrawing []                                   :void)
(extern-c EndDrawing   []                                   :void)
(extern-c CloseWindow  []                                   :void)
(extern-c WindowShouldClose []                              :bool)

(defn main [] :int
  (InitWindow 800 600 "Hello Turmeric")
  (while (not (WindowShouldClose))
    (BeginDrawing)
    (EndDrawing))
  (CloseWindow)
  0)
```

No manual `-I` or `-L` flags needed: `tur build` injects them from the manifest.

## Part 2: Outbound -- CMake Projects Consuming Turmeric Packages

> **Status:** Stretch goal. Scheduled for v2.x or v3.

This section describes `FindTurmeric.cmake` -- a CMake helper that lets
projects written in C or C++ pull in Turmeric libraries via CPM or
`find_package`.

### Design goals

- A CMake maintainer can add a Turmeric library to their project without
  learning any Turmeric tooling.
- Turmeric library authors publish a normal `TurmericConfig.cmake` alongside
  their `build.tur`.
- The generated CMake files are always derived from `build.tur`; there is no
  hand-written CMake in a Turmeric project.

### Step 1: Author generates CMake files

Running `tur emit-cmake` (or `tur publish --cmake`) on a Turmeric library
produces two files:

```
tur-geom/
  CMakeLists.txt         -- standard CMake project wrapper
  TurmericConfig.cmake   -- find_package(Turmeric) support
```

`CMakeLists.txt` (generated):

```cmake
# CMakeLists.txt -- AUTO-GENERATED by `tur emit-cmake`. Do not edit.
cmake_minimum_required(VERSION 3.20)
project(geom VERSION 0.2.1 LANGUAGES C)

find_program(TUR_COMPILER tur REQUIRED)

add_custom_command(
  OUTPUT  "${CMAKE_CURRENT_BINARY_DIR}/geom.c"
          "${CMAKE_CURRENT_BINARY_DIR}/geom.h"
  COMMAND "${TUR_COMPILER}" emit-c
            --output "${CMAKE_CURRENT_BINARY_DIR}/geom"
            "${CMAKE_CURRENT_SOURCE_DIR}/src/vector.tur"
            "${CMAKE_CURRENT_SOURCE_DIR}/src/matrix.tur"
  DEPENDS "${CMAKE_CURRENT_SOURCE_DIR}/src/vector.tur"
          "${CMAKE_CURRENT_SOURCE_DIR}/src/matrix.tur"
  COMMENT "Compiling Turmeric library geom"
)

add_library(geom STATIC "${CMAKE_CURRENT_BINARY_DIR}/geom.c")

target_include_directories(geom
  PUBLIC  "$<BUILD_INTERFACE:${CMAKE_CURRENT_BINARY_DIR}>"
          "$<INSTALL_INTERFACE:include>"
)

add_library(geom::all ALIAS geom)
```

`TurmericConfig.cmake` (generated):

```cmake
# TurmericConfig.cmake -- AUTO-GENERATED by `tur emit-cmake`.
set(geom_VERSION 0.2.1)
set(geom_FOUND   TRUE)
include("${CMAKE_CURRENT_LIST_DIR}/geom-targets.cmake")
```

### Step 2: C/C++ project consumer

A C/C++ project (which may know nothing about Turmeric) adds the library via
CPM:

```cmake
# CMakeLists.txt -- written by the C project author
cmake_minimum_required(VERSION 3.20)
project(my_c_app)

include(cmake/CPM.cmake)

# Pull in Turmeric library
CPMAddPackage(
  NAME    geom
  URL     https://github.com/alice/tur-geom/archive/refs/tags/v0.2.1.tar.gz
  VERSION 0.2.1
)

add_executable(my_c_app src/main.c)
target_link_libraries(my_c_app PRIVATE geom::all)
```

`my_c_app/src/main.c`:

```c
#include "geom.h"   /* auto-generated Turmeric header */

int main(void) {
    geom_vector_2d v = geom_vector_2d_make(1.0f, 2.0f);
    /* ... */
    return 0;
}
```

The Turmeric compiler is invoked transparently by the generated `CMakeLists.txt`
during the CMake build; the C author does not need to know Turmeric is involved.

### `FindTurmeric.cmake`

A reusable `FindTurmeric.cmake` module is distributed as part of the Turmeric
toolchain. It is used by the generated CMake files to locate the `tur` binary
and verify the version:

```cmake
# FindTurmeric.cmake (distributed with tur, installed to CMAKE_MODULE_PATH)
#
# Imported targets:
#   Turmeric::Compiler -- the tur binary as an imported executable
#
# Variables set:
#   Turmeric_FOUND, Turmeric_VERSION, Turmeric_COMPILER

find_program(Turmeric_COMPILER NAMES tur
  PATHS ENV PATH /usr/local/bin /opt/homebrew/bin
  DOC "Path to the Turmeric compiler"
)

if(Turmeric_COMPILER)
  execute_process(
    COMMAND "${Turmeric_COMPILER}" --version
    OUTPUT_VARIABLE Turmeric_VERSION_STRING
    OUTPUT_STRIP_TRAILING_WHITESPACE
  )
  string(REGEX MATCH "[0-9]+\\.[0-9]+\\.[0-9]+" Turmeric_VERSION
         "${Turmeric_VERSION_STRING}")
endif()

include(FindPackageHandleStandardArgs)
find_package_handle_standard_args(Turmeric
  REQUIRED_VARS Turmeric_COMPILER
  VERSION_VAR   Turmeric_VERSION
)

if(Turmeric_FOUND AND NOT TARGET Turmeric::Compiler)
  add_executable(Turmeric::Compiler IMPORTED)
  set_target_properties(Turmeric::Compiler PROPERTIES
    IMPORTED_LOCATION "${Turmeric_COMPILER}"
  )
endif()
```

### `AddTurmericTarget.cmake`

A helper module (also distributed with `tur`) provides the
`add_turmeric_library` and `add_turmeric_executable` CMake functions. This is
what `tur emit-cmake` uses in generated `CMakeLists.txt` files.

```cmake
# cmake/AddTurmericTarget.cmake
include_guard(GLOBAL)
find_package(Turmeric REQUIRED)

# add_turmeric_library(<name> SOURCES <...> [DEPENDS <targets...>])
function(add_turmeric_library name)
  cmake_parse_arguments(ATL "" "" "SOURCES;DEPENDS" ${ARGN})

  set(out_c  "${CMAKE_CURRENT_BINARY_DIR}/${name}.c")
  set(out_h  "${CMAKE_CURRENT_BINARY_DIR}/${name}.h")

  add_custom_command(
    OUTPUT  "${out_c}" "${out_h}"
    COMMAND Turmeric::Compiler emit-c
            --output "${CMAKE_CURRENT_BINARY_DIR}/${name}"
            ${ATL_SOURCES}
    DEPENDS ${ATL_SOURCES}
    COMMENT "Compiling Turmeric library ${name}"
  )

  add_library(${name} STATIC "${out_c}")
  target_include_directories(${name} PUBLIC "${CMAKE_CURRENT_BINARY_DIR}")

  if(ATL_DEPENDS)
    target_link_libraries(${name} PUBLIC ${ATL_DEPENDS})
  endif()

  add_library(${name}::${name} ALIAS ${name})
endfunction()

# add_turmeric_executable(<name> SOURCES <...> [LIBRARIES <targets...>])
function(add_turmeric_executable name)
  cmake_parse_arguments(ATE "" "" "SOURCES;LIBRARIES" ${ARGN})

  set(out_c "${CMAKE_CURRENT_BINARY_DIR}/${name}_main.c")

  add_custom_command(
    OUTPUT  "${out_c}"
    COMMAND Turmeric::Compiler emit-c
            --output "${CMAKE_CURRENT_BINARY_DIR}/${name}_main"
            ${ATE_SOURCES}
    DEPENDS ${ATE_SOURCES}
    COMMENT "Compiling Turmeric executable ${name}"
  )

  add_executable(${name} "${out_c}")

  if(ATE_LIBRARIES)
    target_link_libraries(${name} PRIVATE ${ATE_LIBRARIES})
  endif()
endfunction()
```

## Lock File Behavior for CMake Deps

CMake deps are tracked in `tur.lock` the same as Turmeric spices:

```yaml
cmake-deps:
  raylib:
    url:      "https://github.com/raysan5/raylib"
    ref:      "5.0"
    resolved: "ae2573820d27e1f1..."
    sha256:   "abc123..."
  cjson:
    url:      "https://github.com/DaveGamble/cJSON"
    ref:      "v1.7.16"
    resolved: "f93a..."
    sha256:   "def456..."
```

- `tur fetch` populates these entries.
- `tur build` refuses to proceed if hashes do not match.
- Local `:path` cmake-deps are not recorded.

---

## Security Considerations

- CMake build scripts run arbitrary code. Any `:cmake-deps` entry is a trust
  decision equivalent to executing code from that repository.
- `tur audit` (future) will list all cmake-dep repositories and their
  maintainer GPG keys.
- Hash verification in `tur.lock` ensures code is not silently swapped after
  the first fetch.
- Prefer git tags over branch names for `:ref` to avoid moving targets.

## Packaging a Turmeric Library for CMake Consumers -- Checklist

When a Turmeric library author wants to support CMake consumers:

- [ ] Ensure the package builds cleanly with `tur build --release`
- [ ] Run `tur emit-cmake` to generate `CMakeLists.txt` + `TurmericConfig.cmake`
- [ ] Commit both generated files to the repository
- [ ] Tag the release: `git tag v0.2.1`
- [ ] Push tag and verify CPM can fetch and build it from the tag URL
- [ ] Add a `cmake/` usage example to the repository README

## Implementation Checklist

### Phase A: Inbound (`:cmake-deps`)

- [ ] Parse `:cmake-deps` block from `build.tur`
- [ ] Generate `cmake/SpiceDeps.cmake` from the block
- [ ] Invoke `cmake` in a subprocess to fetch and build deps
- [ ] Generate `cmake/spice-deps-manifest.json` from CMake build output
- [ ] Pass include/lib/link flags from manifest to `tur build` compilation step
- [ ] Add `:cmake-deps` entries to `tur.lock`
- [ ] Verify SHA-256 hashes on re-fetch

### Phase B: Outbound (CMake plugin, stretch goal)

- [ ] Implement `tur emit-cmake` command
- [ ] Template: generate `CMakeLists.txt` from `build.tur` `:exports`
- [ ] Template: generate `TurmericConfig.cmake`
- [ ] Distribute `FindTurmeric.cmake` with the `tur` toolchain install
- [ ] Distribute `AddTurmericTarget.cmake` with the `tur` toolchain install
- [ ] End-to-end test: C project imports Turmeric library via CPM
- [ ] Documentation: "Using a Turmeric library from CMake" guide
