# Plan: Spice `__ok` / `__err` -> Typed Inline-C Builders -- Umbrella

> **Status:** Open. Tracks per-spice migration of hand-rolled inline-C
> result/option struct helpers to the typed preamble builders
> (`tur_ok_ptr` / `tur_err_int` / `tur_some_ptr` / `tur_none` / ...).
> **Last Updated:** 2026-06-24
> **Type:** Spice migration sweep
> **Predecessor:** `docs/upcoming/type-system-c-abi-followups-plan.md`
>   (TC5/TC6/TC7 landed the typed builders + the inline-C-results guide;
>    TC8 migrated rtmidi as the exemplar).
> **Exemplar PR:** `tur-rtmidi v0.2.0` (this commit) -- removed `__ok` /
>   `__err` helpers and `midi-in-of` / `midi-out-of` extractors; constructors
>   now return real `(Result MidiIn int)` / `(Result MidiOut int)`.

---

## Why

The audit (`docs/archive/spices-int-stand-in-audit-2026-06-14.md`) closed
the S2 opaque-handle work across the spice tree, but a wide layer of
fallible inline-C constructors still hand-roll the canonical Result/Option
struct as private `__ok` / `__err` helpers:

```turmeric
(defn __ok [v : int] : ptr<void>
  ```c
  struct { bool is_ok; int64_t ok_val; int64_t err_val; } *r = malloc(...);
  r->is_ok = true; r->ok_val = v; r->err_val = 0; return r;
  ```)
```

These work, but they:

- duplicate the canonical layout in every spice (silent-drift risk if
  the layout ever changes -- the typed builders have a `_Static_assert`
  pinning the bytes; the hand-rolled copies don't);
- force the function to return `:ptr<void>` and ship an `X-of` extractor
  to recover the typed handle, throwing away what the type checker could
  otherwise enforce on the public surface;
- spread the "magic struct" idiom every time a downstream contributor
  copy-pastes from a neighbouring spice.

The typed builders close all three at once. See
`docs/guides/inline-c-results-guide.md` for the worked pattern.

## Migration recipe (per spice)

1. Delete the `__ok` / `__err` (and any `__some` / `__none`) helpers.
2. Change the constructor's return type from `:ptr<void>` to a real
   `(Result Handle E)` / `(Result int int)` / `(Option Handle)` etc.
3. Replace the inline-C body's `malloc(...); r->is_ok = ...; return r;`
   with `return tur_ok_ptr(h);` / `return tur_err_int(code);` /
   `return tur_some_ptr(h);` / `return tur_none();`.
4. Delete the `X-of` extractor; call sites use stdlib `ok-val` /
   `err-val` / `unwrap` directly on the typed result.
5. Drop the extractor from the `:exports` block in `build.tur`.
6. Update the spice's README quick start so the example reads through
   `(ok-val r)`, not a positional `X-of` extractor.
7. Bump the spice's minor version (constructors changed signature -- it
   is an ABI break for in-tree consumers; audit `git grep` before cutting).

The rtmidi v0.2.0 diff is the exemplar -- everything follows the same
shape.

## Out of scope

- Spices whose fallible constructors already use a different pattern
  (e.g. `tur_box_*` directly) -- nothing to migrate, just a follow-up if
  the author wants the typed builder's clarity. Not tracked here.
- Vendored copies under `spices/<x>/spices/<dep>-v0.y.0/` -- those are
  pinned vendored deps; they update when the dep's own release ships.
- Generic `(Result MyStruct MyErr)` builders -- documented as out-of-scope
  in the inline-C-results guide; not required by any row above.
