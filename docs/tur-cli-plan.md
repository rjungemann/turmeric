# `tur new`, `tur run`, `tur add` -- CLI Implementation Plan

> **Status:** Design -- pre-implementation
> **Related:** [package-management-plan.md](package-management-plan.md),
>              [cmake-cpm-integration-plan.md](cmake-cpm-integration-plan.md)

---

## Overview

The three commands below cover the full "zero to running project" workflow
that the Turmeric homepage advertises:

```sh
# Step 1: create a project
tur new my-project
cd my-project

# Step 2: run it
tur run

# Step 3: add a dependency from the Spice registry
tur add spice/http
tur add spice/json
```

This document specifies the exact behavior of each command, the files they
create or modify, and the implementation checklist.

---

## `tur new <name>` / `tur init`

### Purpose

`tur new <name>` scaffolds a new Turmeric project in a new directory called
`<name>`. `tur init` does the same thing inside the current directory (must be
empty or not yet exist as a project). After either command the developer can
`cd <name> && tur run` without any further manual setup.

### Usage

```sh
tur new my-project            # executable project (default)
tur new my-lib --lib          # library project (no main entry point)
tur new my-project --no-git   # skip git init

tur init                      # scaffold inside current directory
tur init --lib                # library project inside current directory
```

### Files created

```
my-project/
  build.tur          -- package manifest
  tur.lock           -- empty lock file (created so VCS can track it)
  src/
    main.tur         -- hello-world entry point
  .gitignore         -- ignores build/, spices/, cmake/
  README.md          -- minimal readme (project name + one-liner)
```

#### `build.tur` (generated)

```turmeric
(defpackage my-project
  :name    "my-project"
  :version "0.1.0")
```

#### `src/main.tur` (generated, executable project)

```turmeric
#lang turmeric

(defn main [] :int
  (println "Hello from my-project!")
  0)
```

#### `src/lib.tur` (generated, library project)

```turmeric
#lang turmeric

;;; greet -- return a greeting string.
;;;
;;; Parameters:
;;;   name -- the name to greet
;;;
;;; Returns:
;;;   A greeting string.
;;;
;;; Example:
;;;   (greet "world")  ; => "Hello, world!"
;;;
;;; Since: 0.1.0
(defn greet [name :str] :str
  (str "Hello, " name "!"))
```

#### `.gitignore` (generated)

```
build/
spices/
cmake/SpiceDeps.cmake
```

#### `tur.lock` (generated, empty)

`tur.lock` uses the same Turmeric S-expression syntax as `build.tur` so it
can be parsed by the same reader and diff'd cleanly in version control.

```turmeric
;;; tur.lock -- generated by tur. Do not edit by hand.
;;; Commit this file to version control for reproducible builds.

(deflockfile
  :format-version 1
  :spices         #{}
  :cmake-deps     #{})
```

### Behavior details

1. **Directory must not exist** (or must be empty). `tur new` exits with a
   clear error if the target directory already exists and is non-empty.

2. **`git init`** is run automatically after scaffold unless `--no-git` is
   passed. If `git` is not on `PATH`, skip silently (do not fail).

3. **Name validation**: `<name>` must match `[a-z][a-z0-9-]*`. Reject names
   that start with a digit or contain uppercase letters; print a suggestion
   (e.g., `"use 'my-project' instead of 'My Project'"`).

4. **`--lib` mode**: omit `src/main.tur`, create `src/lib.tur` instead.
   The `build.tur` gains `:type :lib`.

### Implementation checklist

- [x] Parse `<name>` positional argument and `--lib`, `--no-git` flags;
      for `tur init`, derive name from `$PWD` basename
- [x] Validate name format; print actionable error on bad input
- [x] Create directory tree: `<name>/src/` (`tur new`) or `./src/` (`tur init`)
- [x] Write `build.tur`, `tur.lock`, `src/main.tur` (or `src/lib.tur`),
      `.gitignore`, `README.md` using the templates above
- [x] Run `git init && git add -A && git commit -m "Initial commit"` unless
      `--no-git`; swallow error if `git` absent
- [x] Print success summary, e.g.:
      ```
      Created my-project/
        build.tur
        src/main.tur
        .gitignore

      Run:  cd my-project && tur run
      ```

## `tur run`

### Purpose

Build and execute the current project. Must be run from the project root (the
directory containing `build.tur`), or any subdirectory of it.

### Usage

```sh
tur run                      # debug build + run
tur run --release            # release build + run
tur run --offline            # skip network; fail if any spice missing from disk
tur run -- --flag arg        # pass arguments after -- to the binary
tur run src/other.tur        # run a specific file (no build.tur needed)
```

### Behavior

1. **Locate project root** -- walk up from `$PWD` until a `build.tur` is
   found (same convention as Cargo, Go). Error if none found.

2. **Read `build.tur`** -- parse the `defpackage` form for `:name`,
   `:version`, `:spices`, `:cmake-deps`, `:build-opts`.

3. **Resolve dependencies** -- read `tur.lock`; fetch any missing spices into
   `spices/`. Fail if a spice hash does not match `tur.lock`. (For the initial
   implementation without a live registry, only Git-URL and path spices are
   supported.)

4. **Compile** -- invoke the Turmeric compiler on `src/main.tur` (or the
   configured entry point) with spice include paths and C link flags resolved
   from cmake-deps.

5. **Execute** -- run the resulting binary, forwarding any arguments that
   appeared after `--`.

6. **Exit code** -- `tur run` exits with the same code as the binary.

### Entry point resolution

| Condition | Entry file |
|---|---|
| `build.tur` has `:entry "src/foo.tur"` | `src/foo.tur` |
| `src/main.tur` exists | `src/main.tur` |
| Single `*.tur` file in `src/` | that file |
| None of the above | error with suggestion |

### Implementation checklist

- [x] Walk up from `$PWD` to find `build.tur`; friendly error if not found
- [x] Parse `defpackage` from `build.tur`
- [ ] Read `tur.lock`; verify SHA-256 of any already-fetched spices
- [ ] Fetch missing spices (git clone to `spices/<name>-<ref>/`); skip fetch
      and error if spice absent when `--offline` is set
- [ ] Generate `cmake/SpiceDeps.cmake` from `:cmake-deps` if present; invoke
      CMake to build C deps
- [x] Resolve entry point (see table above)
- [ ] Invoke `tur` compiler with correct `-I` (spice paths) and `-L`/`-l`
      (C link flags); pass `--release` flag if requested
- [x] Execute binary, forward stdin/stdout/stderr, propagate exit code
- [x] `--` passthrough: everything after `--` is forwarded to the binary argv

### Prerequisites

Before the remaining `tur run` items can be implemented, the following
infrastructure must be in place:

- [ ] **Spice include path convention** -- define the `-I` path layout for
      fetched spices (`spices/<name>-<ref>/src` or `spices/<name>-<ref>/`);
      document in [package-management-plan.md](package-management-plan.md)
- [ ] **Compiler `-I` flag support** -- ensure the Turmeric compiler accepts
      one or more `-I <dir>` flags to add include search paths; needed before
      spice paths can be forwarded from `tur run`
- [ ] **SHA-256 archive helper** -- `pkg_sha256_dir()` that tarballs a
      fetched spice directory and returns its SHA-256; used by both `tur run`
      (verification) and `tur fetch` (initial recording).  The per-file
      `pkg_sha256_file()` already exists; the directory variant is missing
- [ ] **CMake integration path** -- decide whether `tur run` invokes CMake
      inline or whether a prior `tur fetch` is required; document the
      contract in [cmake-cpm-integration-plan.md](cmake-cpm-integration-plan.md)

## `tur add <package>`

### Purpose

Add a dependency to the current project. Updates `build.tur` and `tur.lock`
in place.

### Usage

```sh
# Spice registry (short name -- requires registry)
tur add spice/http
tur add spice/json
tur add spice/postgres

# Git URL (works today, no registry needed)
tur add https://github.com/alice/tur-geom
tur add https://github.com/alice/tur-geom --ref v0.2.1

# Local path
tur add ../tur-utils --path

# CMake/C dependency
tur add --cmake https://github.com/raysan5/raylib --ref 5.0
```

### Short name resolution (`spice/<pkg>`)

`spice/http` is shorthand for a package on the official Spice registry at
`https://pkg.turmeric-lang.org`. The registry maps `spice/http` to a canonical
Git URL + latest stable ref. The resolved URL and exact SHA are written to
`tur.lock`.

Until the registry is live, `tur add spice/<pkg>` prints a clear message:

```
The Spice registry is not yet available.
Add the package directly with a Git URL:
  tur add https://github.com/turmeric-spice/tur-http --ref v0.1.0
```

### `build.tur` mutation

`tur add` appends (or updates) a `:spices` entry in `build.tur`. Given:

```turmeric
(defpackage my-app
  :name    "my-app"
  :version "0.1.0")
```

After `tur add https://github.com/alice/tur-geom --ref v0.2.1`:

```turmeric
(defpackage my-app
  :name    "my-app"
  :version "0.1.0"
  :spices #{
    "geom" #{:url "https://github.com/alice/tur-geom"
             :ref "v0.2.1"}
  })
```

Rules:
- The **spice name** defaults to the last path component of the URL, with any
  `tur-` prefix stripped (e.g., `tur-geom` -> `geom`). Use `--name foo` to
  override.
- If `:spices` already exists, the new entry is appended inside the existing
  map literal. Formatting is preserved for existing entries.
- If `--cmake`, the entry goes into `:cmake-deps` instead of `:spices`.

### `tur.lock` update

After updating `build.tur`, `tur add` immediately fetches the new spice,
resolves the full commit SHA, computes the SHA-256 of the archive, and
writes the lock entry:

```turmeric
(deflockfile
  :format-version 1
  :spices #{
    "geom" #{:url        "https://github.com/alice/tur-geom"
             :ref        "v0.2.1"
             :resolved   "a1b2c3d4..."   ;;; full commit SHA
             :sha256     "abc123..."
             :fetched-at "2026-05-14T10:00:00Z"}
  }
  :cmake-deps #{})
```

If `--ref` is omitted, the tool resolves the default branch HEAD and warns:

```
Warning: no --ref specified; resolved to HEAD (a1b2c3d4).
Pin with: tur add https://github.com/alice/tur-geom --ref a1b2c3d4
```

### Error cases

| Condition | Error message |
|---|---|
| Not in a project directory | `No build.tur found. Run tur new <name> to create a project.` |
| Spice already in `build.tur` | `'geom' is already a dependency. Use tur update geom to change the ref.` |
| Network failure | `Failed to reach https://github.com/...: <reason>` |
| Ref not found | `Ref 'v99.0.0' not found in https://github.com/alice/tur-geom` |
| SHA mismatch on re-fetch | `Integrity check failed for 'geom'. Run tur fetch --force to re-download.` |

### Prerequisites

Before `tur add` can be implemented, the formatter must support comment
preservation end-to-end. The required formatter tasks are:

- [ ] **Formatter: parse comments as AST nodes** -- comments must survive a
      parse -> emit round-trip rather than being stripped
- [ ] **Formatter: round-trip fidelity test** -- add a test suite that verifies
      `format(parse(src)) == src` for files containing inline and block comments
- [ ] **Formatter: re-emit `defpackage` form** -- ensure the formatter can
      pretty-print `defpackage` with nested map literals (`:spices`, `:cmake-deps`)
      without collapsing whitespace in ways that would confuse a diff

See [formatter-guide.md](guides/formatter-guide.md) for the formatter spec.

### Implementation checklist

- [x] Parse positional `<package>` arg; detect `spice/` prefix vs. URL vs.
      local path; handle `--ref`, `--name`, `--path`, `--cmake` flags
- [x] Locate project root (same walk-up logic as `tur run`)
- [ ] Parse existing `build.tur` into a formatter-aware AST (comments as nodes)
      *(deferred -- formatter prerequisites not yet complete)*
- [x] Resolve spice name from URL or `--name` override
- [x] Detect duplicate; exit with friendly error if already present
- [x] Fetch spice: `git clone --depth 1 --branch <ref> <url> spices/<name>-<ref>/`
- [ ] Compute SHA-256 of the fetched directory archive
- [ ] Mutate the AST (insert new spice entry into `:spices` map node) and
      re-emit via `tur format`; write result back to `build.tur`
      *(deferred -- formatter prerequisites not yet complete)*
- [x] Write or update `tur.lock` with resolved SHA and fetched-at timestamp
- [x] Print confirmation:
      ```
      Added geom v0.2.1
        build.tur updated
        tur.lock updated
      ```
- [x] (Registry) `spice/<pkg>` prints "not yet available" message with
      suggested git URL; full lookup deferred until registry is live

## Open questions

1. **`tur new` vs. `tur init`**: **Resolved** -- follow Rust/Cargo convention:
   `tur new <name>` creates a new directory; `tur init` scaffolds inside an
   existing directory (like `git init`). Both produce the same file layout.

2. **`build.tur` AST editing**: **Resolved** -- use a formatter-aware AST
   editor. Parse `build.tur` into a full AST (preserving comments as nodes),
   mutate the tree, and re-emit via `tur format`. This requires the formatter
   to round-trip comments correctly, which should be treated as a hard
   requirement before `tur add` is implemented. Prerequisite: formatter
   comment-preservation (see [formatter-guide.md](guides/formatter-guide.md)).

3. **`tur.lock` file format**: **Resolved** -- use Turmeric S-expression syntax
   (same as `build.tur`) rather than YAML. This means a single reader handles
   both files, diffs are consistent with the rest of the project, and the
   formatter can pretty-print lock files without a separate YAML library.
   The top-level form is `deflockfile` to distinguish it from `defpackage`.
   Maps are written with `#{}` (the standard Turmeric map literal) rather than
   `{}` (curly-infix, which requires `#lang turmeric/curly-infix`).

4. **Offline mode**: **Resolved** -- add an explicit `--offline` flag to
   `tur run` and `tur build`. With `--offline`, all network activity is skipped
   and the command fails only if a required spice is missing from `spices/` on
   disk. Without the flag, normal fetch behavior applies.

5. **Entry point in `build.tur`**: **Resolved** -- support an optional
   `:entry "src/main.tur"` key in `build.tur` for explicit override; fall back
   to inference when absent (see entry point resolution table in `tur run`
   section).
