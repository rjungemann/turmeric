#
# NAMES, not a count, and deliberately so. A count rots into a rubber-stamp:
# it cannot tell "the three known ones" from "one of those got fixed and two
# new ones appeared", which is exactly the shape
# docs/reported/jit-suite-reports-pass-when-the-engine-is-disabled.md was filed
# about. The CI job diffs this list against the run and fails on ANY
# difference, including a fixture that starts passing -- if you fix one, delete
# its line in the same commit.
#
# Blank lines and #-comments are ignored. One fixture name per line.
#
# This file exists so the split leg can be GREEN while the split is still
# incomplete. It is scaffolding for an opt-in feature under development, not a
# permanent allowance: when the list empties, delete the file and the baseline
# comparison with it, so the job simply asserts zero failures like every other
# suite.

# This list describes the SPLIT CI JOB's configuration: Linux, Debug, system
# gcc. It is not a claim about every platform.
#
# Two fixtures were in this list and are not any more, because they PASS in
# that configuration: `gc-registry-growth` and `sx8a-tur-smt-div-mod`. They
# still FAIL on Windows, and that is a real split defect, not a measurement
# artifact. What has been established, by experiment rather than inference:
#
#   - NOT the build type. They were first seen on a Release Windows build, and
#     CLAUDE.md warns a Release `tur` elides contract checks -- exactly how a
#     fixture fails with the wrong error. Rebuilt Debug on Windows: both still
#     fail. Eliminated.
#   - NOT the fixture, and not a link failure. Same compiler, same build, same
#     fixture: DEFAULT mode prints 20000 and exits 0; --runtime=split produces
#     no output and exits 127. `nm` finds gc_all_blocks_count in both binaries,
#     so the symbol resolves; the split binary is simply 492K against 228K.
#   - NOT recursion depth. gc-registry-growth builds a 20000-deep chain, and a
#     hand-written 20000-deep recursion runs fine under split on Windows.
#     Eliminated.
#   - NOT a missing DLL. `ldd` resolves everything.
#
# So: a genuine Windows-only split defect somewhere in the rc/GC machinery,
# failing before any output reaches stdout. Two variables remain uncontrolled
# (Windows vs Linux, MinGW gcc 16.1 vs system gcc) and cannot be separated on a
# Windows box alone.
#
# Next diagnostic, cheapest first: the WIN32 split archive also pulls in
# async/tur_sjlj_x64_win.S (see add_library(turt_preamble ...) in
# src/CMakeLists.txt), which the default path gets from elsewhere -- check for a
# duplicate or divergent unwinding/setjmp implementation between the archive and
# the emitted program half.
#
# These are deliberately NOT listed as expected failures: this file is the
# Linux job's baseline, and listing a fixture that passes there would make the
# job red forever. When a Windows split leg exists, it needs its own baseline.

# The one place the split is genuinely LOSSY, and it is understood rather than
# mysterious. The emitted preamble is not fixed across programs: the emitter
# picks EITHER `#include "hamt.h"` (for a program using hamt directly) OR the
# loose `extern void *tur_hamt_new();` declarations from stdlib's extern-c --
# never both. The committed decls region is generated from ONE canonical
# emission, so it freezes whichever that program chose, and hands it to every
# other program.
#
# c2mir accepts the loose declaration alongside hamt.h's
# `Hamt *tur_hamt_new(void)`; gcc does not. This fixture is the minority case
# that wants the header, so it fails LOUDLY at compile time --
#   implicit declaration of function 'tur_hamt_eq_dynamic'
#   assignment to 'void *' from 'int' makes pointer from integer without a cast
# -- which is the safe direction to be wrong in.
#
# FIXED 2026-09-07, and by neither of the two directions guessed at here
# ("carry both shapes" / "make the extern-c declarations agree with the
# header"). Both would have been substantial; both were unnecessary.
#
# The information was never actually lost -- it was discarded. The replaced
# preamble region contained THIS program's own `#include "hamt.h"`, and the
# swap threw it away along with everything else in that region.
# jit_try_split_preamble now re-emits the quoted includes it finds there
# (src/main.c), so every program gets exactly what it emitted. That is the
# monolithic behaviour restored, so neither shape has to lose and nothing had
# to be reconciled.
#
# Verified on 133 hamt/map/dict/set fixtures under split: 0 failed. Quoted
# includes only -- `<...>` system headers stay the decls region's business, and
# re-emitting those on Windows would feed the JIT the MinGW SDK headers it
# demonstrably cannot digest.
